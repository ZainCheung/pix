# Pix wire protocol v1

This directory documents the plaintext application schema encoded and decoded
by `pix-wire`. These messages are never sent directly over TCP or the relay.
The secure-channel layer authenticates and encrypts each encoded message first.

## Envelope

Client requests contain:

- `protocol`: integer major version, exactly `1`;
- `request_id`: connection-scoped unsigned integer;
- `type`: dotted operation name;
- operation-specific fields.

Server messages contain:

- `protocol`: integer major version, exactly `1`;
- optional `request_id` when acknowledging or answering a request;
- `type`: dotted event name;
- event-specific fields.

Unknown enum variants and incompatible major versions fail closed. Request IDs
deduplicate only within the current authenticated connection.

## Requests

`host.snapshot`, `host.defaults`, `workspace.list`, `session.list`, `session.create`,
`session.attach`, `session.rename`, `session.release`, `session.prompt`,
`session.steer`, `session.follow_up`, `session.abort`, `session.compact`,
`model.list`, `model.set`, `thinking.set`, and `extension_ui.respond`.

## Events

`request.ack`, `host.snapshot`, `host.defaults`, `workspace.list`, `workspace.changed`,
`session.list`, `session.snapshot`, `session.state`, `user.message`,
`assistant.delta`, `assistant.message`, `tool.start`, `tool.update`, `tool.end`,
`extension_ui.request`, `compaction`, `model.list`, and `error`.

## `host.defaults`

`host.defaults` reads Pi's persisted model selection and model catalog without
starting a session runtime. The response is scoped to the authenticated host
connection and contains only non-secret model metadata:

```json
{
  "model": {"provider": "opencode-go", "id": "deepseek-v4-flash", "name": "DeepSeek V4 Flash", "reasoning": true},
  "models": [],
  "thinking_level": "high"
}
```

When Pi has not persisted a selection, `model` and `thinking_level` may be
omitted/null and `models` may be empty. Pix never substitutes a product or
model name for an empty host response.

## `host.snapshot` relay access

The `host.snapshot` event may include an optional `relay` object:

```json
{"relay": {"url": "wss://relay.example.com", "channel_secret": "base64url"}}
```

It is present only when the host has an active relay endpoint configured and
identifies the requesting device's durable rendezvous channel. The secret is
delivered exclusively inside the authenticated encrypted channel and must be
stored by clients with the same protection as host trust material. Clients
without relay support ignore the field.

## `session.list` limit

`session.list` may include an optional `limit` integer. When present, the host
returns at most that many sessions, newest first, and never more than 200.
Omitted `limit` keeps the previous unbounded list. The response shape is
unchanged. Clients without this field continue to work.

Home does not use a `home.snapshot` aggregate. Workspace rows load first;
session summaries load when a workspace expands.

## Relay transport

The relay carries the same length-prefixed encrypted records as direct TCP;
it terminates WebSockets, never the Pix secure channel.

Derivations (implemented once in `pix-wire`, fixture
`protocol/fixtures/v1/relay-channel.json`):

- `channel_id = hex(Blake2s256("Pix relay channel v1" || secret))`;
- `join_proof(role) = hex(Blake2s256("Pix relay join v1" || role || secret))`
  with `role` being the ASCII string `host` or `client`.

Join request: `GET {relay}/v1/channel/{channel_id}` upgrading to WebSocket
with headers `X-Pix-Protocol: 1`, `X-Pix-Role: host|client`, and
`X-Pix-Join-Proof`. The relay pins the first proof per role and role
cardinality is one connection; a newer valid join supersedes the older one
(close 4008).

Messages:

- binary: exactly one length-prefixed encrypted record (at most
  1 MiB + 4 bytes), forwarded verbatim to the opposite role, dropped without
  queueing when the peer is absent;
- text from relay to endpoint: `{"type":"peer_joined"}` and
  `{"type":"peer_left"}`;
- text from endpoint to relay: protocol violation, connection closed.

The QR payload for remote pairing is
`pix://pair?v=1&relay={ws-url}&secret={channel_secret}&fp={host_fingerprint}`
with a percent-encoded relay URL. The same rendezvous can be entered by
typing an eight-character Crockford join code `XXXX-XXXX` plus the relay
URL; the channel secret is derived in `pix-wire` as
`Blake2s256("Pix remote join v1" || normalized_code || 0x00 || relay_url)`.
The pairing channel is single-use and expires two minutes after
presentation; the Noise XX flow, token, and six-digit confirmation are
identical to LAN pairing.

## Resource limits

- encrypted frame: 1 MiB;
- any decoded string: 512 KiB;
- pending requests per authenticated connection: 128;
- outer stream prefix: unsigned 32-bit length in network byte order;
- relay WebSocket message: one encrypted frame plus its 4-byte prefix.

Fixtures under `protocol/fixtures/v1` are canonical Rust-generated byte
sequences and must be decoded unchanged by Swift tests. The set includes one
file per request and event type, plus pairing, confirmation, fingerprint,
expiry, and maximum-frame rejection fixtures. Generate them with
`cargo run -p pix-wire --example generate_fixtures`.
